## 3. 웹 플랫폼 · Tailwind · 접근성 표준

- **Tailwind 최신 4.3.3 (2026-07-16)**, v5 없음. 4.1(2025-04): `text-shadow-*`, `mask-*`, `user-invalid:`. 4.2(2026-02): 새 팔레트 **mauve·olive·mist·taupe**, 논리 속성 유틸. 4.3(2026-05): `scrollbar-thumb-*`/`scrollbar-track-*` 색.
- **Baseline**(webstatus.dev): `color-mix()`·oklch 널리 사용 가능(2025-11), `:user-invalid` 널리(2026-05), `dvh` 널리(2025-06), `@starting-style` 새로(2024-08), `field-sizing` 새로(2026-06). anchor positioning·`closedby`·invoker commands·`base-select`·`reading-flow`·scroll-driven animation은 한쪽 브라우저가 비어 기본값 부적합. `word-break: auto-phrase`는 일본어 전용, `text-autospace`는 한글-라틴 사이에 작동 안 함 → 한국어는 `keep-all` 유지.
- **접근성**: WCAG 2.2가 ISO/IEC 40500:2025(2025-10-21). EN 301 549 V4.1.1(2026-09-02, WCAG 2.2 AA 정렬, 관보 인용 전). WCAG 3 초안 2026-09-10, 몇 년 더. **APCA는 WCAG 3 초안에서 빠졌고** 대비 알고리즘 미정 → WCAG 2 대비비 유지. forced-colors에서 box-shadow는 사라진다.

## 5. 보류한 것 (이유)

- ~~**Google DESIGN.md 포맷 호환**~~ → **0.4에서 반영**: 템플릿 섹션 제목을 design.md 이름으로, `design-md-sync.mjs`가 tokens.css에서 `colors`·`typography`·`rounded`·`spacing`을 생성(`--check`로 드리프트 방지). 공식 CLI(`@google/design.md lint`) 오류 0·경고 0, 0.3 템플릿은 토큰 0개 인식이었다. `§8` 참조는 섹션 이름으로 바꾸고 구버전 안내를 남겼다.
- ~~**forced-colors 에뮬레이션 패스**(audit)~~ → **0.3에서 반영**: design-audit가 고대비 에뮬레이션으로 윤곽·포커스를 검사하고, tokens.css가 고대비에서 버튼에 안쪽 outline을 그린다.
- ~~**APCA 병행 계산**~~ → **0.4에서 반영(참고값만)**: `apcaLc()`(apca-w3 참조값 6개와 소수 4자리 일치). `tokens-contrast --apca` 표와 design-audit 대비 미달 메시지에 Lc를 붙인다. 판정·exit 코드는 계속 WCAG 2.2 대비비.
- ~~**스크롤 가장자리 fade 마스크 토큰**~~ → **0.4에서 반영**: `--ui-gradient-fade-x/-y`(smoothstep 8단 알파, `--ui-fade-size`). Tailwind 4.3.3에서 `[mask-image:var(…)]`·`mask-(--…)` 둘 다 컴파일, Chromium에서 유효한 그라데이션으로 풀리는 것 확인.
- ~~**`globals.css`의 `@theme` 원색 검사**~~ → **0.3에서 반영**: 필요가 생길 때가 아니라 **우회 통로**였다(`bg-[#…]`가 막히면 `@theme`에 원색을 정의해 피해 감). globals.css·tailwind.config.*를 검사하고 DESIGN.md `tokens_path` 파일만 제외한다.
- ~~**모노레포 per-app DESIGN.md**~~ → **0.4에서 반영**: 편집 파일에서 가장 가까운 DESIGN.md(하위 폴더는 `ui_skill_set:` 키가 있을 때만), `install.mjs --app`. 테스트 중 `--app`으로 없는 폴더를 줄 때 쓰기 실패하던 버그도 발견해 고쳤다.
- ~~**규칙 발동 로그 → 수정률**~~ → **0.4에서 반영**: `.claude/ui-lint/log.jsonl`(자기 gitignore), 편집 전 차단→수정/예외/포기, 종료 전 지적→다음 종료 때 남은 수. `design-lint.mjs --stats`.
- **`light-dark()`로 다크 토큰 재작성: 검토 후 하지 않음 (2026-09-23).** 얻는 것은 JS 한 줄(시스템 다크 따르기 스크립트) 제거뿐이다. 잃는 것: ① tokens.css를 읽는 도구 셋(tokens-contrast·figma-sync·design-md-sync)이 `:root`/`[data-theme=dark]` 두 블록 구조를 전제한다. 기존 프로젝트의 tokens.css는 `--update`로 안 바뀌므로 도구가 두 형식을 모두 읽어야 한다. ② `light-dark()`는 색에만 쓸 수 있어서 그림자·다크 전용 시맨틱 재매핑(basement/layer/solid)은 어차피 별도 규칙이 남는다. ③ 널리 사용 가능(Baseline widely) 시점은 2026-11이다. **다시 볼 조건**: 한 화면 안에서 섹션별로 테마를 섞는 요구(`color-scheme`을 요소 단위로)가 생기거나, 인라인 스크립트를 둘 수 없는 환경(엄격한 CSP)이 나오면.
