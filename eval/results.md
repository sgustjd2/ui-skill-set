# 일관성 실측 기준선 (2026-09-03)

PRD G4("같은 프롬프트 3번 → 팔레트·폰트·라디우스 같음")의 첫 실측. 골든 프롬프트 5개를 각각 **레이아웃·구조만 다르게 3번** 구현하고(고정 요소는 동일), `consistency.mjs`로 측정.

> 주의: 3 run을 한 세션의 한 모델이 만들었으므로 완전히 독립적인 3작업자만큼 발산이 크지 않다. 그래도 "같은 역할에 같은 토큰을 반사적으로 고르는가"는 유효하게 드러난다. 실제 팀 데이터로 다시 재는 것이 이상적.

## 결과

| 프롬프트 | 표면 | 전역 Jaccard | 코어 역할 일치 | 하드 위반 | 판정 |
|---|---|---|---|---|---|
| 01 설정 | Operate·폼 | 66.7% → **100%** † | 91.7% → **100%** † | 0 | PASS |
| 02 로그인 | Operate·폼 | 81.3% | **100%** | 0 | PASS |
| 03 빈 상태 | Operate | 80.0% | **100%** | 0 | PASS |
| 04 요금제 | Persuade·카드 | 82.4% | **100%** | 0 | PASS |
| 05 테이블 | Operate·데이터 | **100%** | **100%** | 0 | PASS |

† 01은 삭제 버튼 스타일(아웃라인 vs 솔리드)이 유일한 발산이었다. DESIGN.md §7에 파괴적 버튼 규약(강조도 기반)을 못박은 뒤 재측정하니 전역·코어 모두 100%.

## 읽는 법

- **코어 역할 일치 = 5개 프롬프트 전부 100%.** 화면 배경·콘텐츠 표면·1차 버튼·뉴트럴 텍스트·온-솔리드 텍스트·컨트롤 라디우스 — 구조 역할은 독립 구현 3개가 항상 같은 토큰을 골랐다. 토큰 어휘가 모호하지 않다는 뜻.
- **전역 Jaccard의 발산은 전부 비코어(정당한 선택).**
  - 01: 삭제 버튼 스타일 → 규약으로 해소
  - 02: 로그인 카드 유무, 전이 시간 유무
  - 03: 아이콘 배경 모양(원 vs 사각), 전이 시간
  - 04: 추천 카드 그림자, 추천 배지 유무
  - 05: 없음(완전 일치)
- 발산이 코어로 새면 DESIGN.md 규약을 조이라는 신호다(01이 그 예). 비코어 발산은 팀이 열어 둘지 닫을지 선택한다.

## 재현

```bash
# 각 프롬프트의 고정 요소를 레이아웃만 다르게 run1·2·3 에 구현한 뒤:
node eval/consistency.mjs <runsDir>            # 전역 Jaccard
node eval/consistency.mjs <runsDir> --roles    # 역할별(코어) 일치
```
