# eval — 일관성 측정

목표(PRD G4): 같은 프롬프트를 여러 번 돌려도 팔레트·폰트·라디우스 사용 토큰 집합이 같고, 하드 룰 위반이 0이어야 한다.

## 골든 프롬프트

`prompts/01`~`05`. 제품 UI 4개(Operate)와 요금제 1개(Persuade). 각 파일은 붙여 넣을 프롬프트 + 유도되는 슬롭 + 기대 결과 + **고정 요소**를 담는다.

- 01 계정 설정 화면 · 02 로그인 폼 · 03 빈 상태 · 04 요금제 · 05 사용자 테이블

### 고정 요소 — 왜 중요한가

Jaccard는 "run들이 공유하는 토큰 / 등장한 토큰 전체"다. 그래서 run마다 **기능(요소)이 다르면** 토큰도 다를 수밖에 없어 Jaccard가 낮게 나온다 — 이건 스타일 불일치가 아니라 기능 차이다. 예: 테이블 run에 1차 버튼이 없으면 `bg-brand-solid`가 안 나오는 게 당연하다.

그래서 각 프롬프트의 **"고정 요소"** 목록을 run1·2·3에 **동일하게** 구현한다. 요소 집합이 같으면 Jaccard가 곧 "같은 요소를 같은 토큰으로 그렸는가" = 스타일 일치도가 된다. 요소를 빼거나 더하지 않는다. 레이아웃·구조는 자유.

## 절차

1. ui-skill-set이 설치된 테스트 프로젝트를 연다.
2. 프롬프트 하나를 골라 새 세션에서 그대로 붙여 넣는다. 프롬프트의 **고정 요소를 전부, 이것만** 구현하고 `runs/<프롬프트>/run1/`에 저장.
3. 세션을 3번 반복해 `run2/`, `run3/`에 저장. 매번 같은 고정 요소를 구현(레이아웃은 달라도 됨).
4. 측정:

```bash
node eval/consistency.mjs runs/01-settings
```

## 읽는 법

```
실행       파일  토큰  하드위반
run1         2    18       0
run2         2    17       0
run3         2    19       0

공유 토큰 15 / 합집합 22 · 일관성(Jaccard) 68.2% (임계 60%)
  run3 고유: bg-informative-weak, text-fg-informative

판정: PASS (하드 위반 0 · 일관성 OK)
```

- **하드위반**: R1~R4(그라데이션·AI-purple·하드코딩 색/폰트) 개수. 하나라도 있으면 FAIL.
- **일관성(Jaccard)**: 실행 전체가 공유하는 토큰 / 등장한 토큰 전체. 임계 60% 미만이면 FAIL. 낮으면 "고유" 줄이 발산 원인을 보여준다.
- 발산이 잦으면 DESIGN.md의 규약이 모호하다는 신호다. 해당 역할 토큰을 명시하거나 컴포넌트 규약(§7)을 조인다.

## 역할별 일치 (`--roles`)

전역 Jaccard는 **기능 차이를 불일치로 오판**한다(테이블엔 1차 버튼이 없어 `bg-brand-solid`가 안 나오는 식). `--roles`는 토큰을 카테고리(화면 배경·콘텐츠 표면·1차 버튼·뉴트럴 텍스트·컨트롤 라디우스…)로 나눠 **카테고리별**로 일치를 재고, 한 실행에 없는 카테고리는 점수에서 뺀다. 그래서 "같은 요소를 같은 토큰으로 그렸는가"만 남는다.

```bash
node eval/consistency.mjs runs/01-settings --roles
```

```
카테고리          코어 실행  일치    토큰
화면 배경           Y    3     100%  bg-basement
콘텐츠 표면          Y    3     100%  bg-layer-default
1차 버튼 배경        Y    3     100%  bg-brand-solid, bg-brand-solid-pressed
뉴트럴 텍스트         Y    3     100%  text-fg-neutral, text-fg-neutral-muted
컨트롤 라디우스        Y    3     100%  rounded-control
상태 텍스트          ·    2      50%  text-fg-critical, text-fg-positive

코어 카테고리 평균 일치 100% (6개, 임계 80%)
판정: PASS
```

- **코어(Y)**: 화면마다 늘 있고 같은 토큰이어야 하는 좁은 구조 역할. 이들의 평균 일치가 **80% 미만이면 FAIL**.
- 코어가 아닌 카테고리(상태색·그림자·배지 등)는 기능에 따라 있고 없고 하므로 점수에서 빠지고, 참고용으로만 표시된다.
- 두 지표는 상보적이다. **전역 Jaccard**(기능 고정형 프롬프트로)로 전체 안정성을, **`--roles`**로 기능과 무관한 구조 스타일 일치를 본다. 좋은 결과는 둘 다 PASS다. 코어가 100%인데 전역 Jaccard가 낮으면 "스타일은 같고 기능만 달랐다"는 뜻이다.
